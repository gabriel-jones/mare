# Phase A integration contract

Build a local playable Three.js colony foundation. Existing art viewer stays at `/`; game lives at `/game/`. Three imports use `../node_modules/three/` via import map. No bundler. Assets `../astronaut.glb`.

Coordinates: Three Y up. Grid cell size 2 metres, integer x/z cell centers `(x*2, z*2)`. World bounds x/z -18..18 cells. Player starts `(0,0,8)` in world metres. Flat buildable center, uneven peripheral terrain. Structures collide except habitats (walkable interior with auto roof hiding).

## sim.js (simulation owner)
Export `DEFS` object: `solar`, `battery`, `hopper`, `habitat`, `lamp`. Each `{name,w,d,cost:{metal,silicon},buildTime,description}`. Export `createState(seed=1847)`: JSON state `{version:1,seed,time:0,inventory:{metal:...,silicon:...},player:{x:0,z:8,y:0},buildings:[],nextId:1,power:{generation:0,demand:0,stored:0,capacity:0}}`. Building `{id,type,x,z,rotation,progress:0,built:false}` coordinates cells, rotation 0/1 swaps footprint w/d. State building positions are minimum cell of footprint (not center).
Export `footprint(type,x,z,rotation)` array `{x,z}`. `validatePlacement(state,type,x,z,rotation)` returns `{ok,reason}` bounds, pad-reserved area x -4..4,z -8..-2, overlap, costs. `placeBlueprint(...)` returns `{ok,reason,id}` and deducts resources on acceptance. `construct(state,id,dt)` returns `{ok,reason}` only when player within 5 metres of footprint center; increases progress/built. `tick(state,dt)` updates time (day duration 240s), power based on solar day cycle `daylight = max(0,sin(time/240*2PI + PI/3))`, batteries capacity and demands, lamps demand at night. `serialize(state)` -> string; `deserialize(text)` validated state or throws. `cancelBlueprint(state,id)` refund unbuilt. No THREE/DOM imports. Include meaningful node:test tests in sim.test.mjs; add game package.json type module if needed. Build phase no mining/research.

## world.js (world/render owner)
Export async `createWorld(canvas,state)` returns `{renderer,scene,camera, update(state,dt), pick(clientX,clientY), setGhost(type,x,z,rotation,valid), clearGhost(), resize(), dispose()}`. `pick` returns `{x,z,worldX,worldZ,buildingId?}` or null using canvas rect. Import DEFS/footprint from sim.js. Fullscreen canvas. Scene terrain seeded rocks/craters, lunar dark background, Starship/pad centered `(0,-10)` world (reserved cells above), astronaut loaded GLB at state.player; follow isometric orthographic camera, no orbit needed; zoom wheel. Astronaut placeholder until loaded, load failure should not break gameplay. Display building meshes for sim buildings; blueprint transparency; completed clear silhouettes; habitat interior accessible auto roof hide when player inside. Grid lines and placement ghost, green/red. Flat ground y0 central +/-25m; supply `state` values update time lighting and emissive base lamps. player y set by main for jumping. Performance: share geometries/materials/cache no rebuilding each frame. No input keyboard listeners (main owner), only zoom canvas listener. Do not mutate sim state. Procedural meshes for structures okay.

## ui.js + game.css (UI owner)
Export `createUI(root,{onSelect,onRotate,onSave,onLoad,onReset,onCancel,onTimeToggle})` returns `{update(state,view), notify(message), dispose()}`. view `{selectedType,rotation,placementReason,nearbyBuilding,constructing,night,paused,saveStatus}`. Construction palette selects type or null; clear keyboard instructions WASD move, Space jump, click place, hold E build nearby, R rotate, Esc cancel. Header resources and power, mission panel opening checklist based on built solar,battery,habitat,hopper. Save/load/reset controls; reset confirmation via inline confirmation if desired. Toggle accelerated time optional label clear. Notice user-friendly local prototype, solo only. UI responsive 640px panel, desktop. Root pointer-events none with controls pointer-events auto. UI owns inner markup, CSS no canvas sizing beyond page. No sim mutation or world access. Selection hotkeys main. Polished dark lunar amber interface, game-first, unobtrusive. All callbacks only, no global handlers.

## main.js + index.html (orchestrator owner)
Input, movement/collision, interaction, placement raycast, fixed-step tick, persistence localStorage, render and UI orchestration. Tests/integration. No other agent edits these.

## Phase B additions
Definitions move to `defs.js` (re-exported by `sim.js`): adds `conveyor` (1×1, walkable), `processor` (2×3), `storage` (1×1); habitat and conveyor are `walkable`. Rotation is 0–3 (odd rotations swap w/d); models face +Z at rotation 0, turned by `rotation*PI/2`. Directions `DIRS=[[0,1],[1,0],[0,-1],[-1,0]]`. Definitions may declare `inputs`/`outputs` ports `{x,z,dir}` in local cells; `ports(b,kind)` returns world `{cell,dir,neighbor}`.
State version 2 adds `reserves:{oxygen}`, `robots:[{id,type:'rover',x,z,heading,task,cargo,charge,...}]`, `miningArea:{x,z}|null`, `mined:{'x:z':remaining}`; buildings may carry `items`, `inventory`, `input`, `output`, `progress`. Version 1 saves migrate with the starter rover. New sim exports: `deconstruct(state,id)`, `collectStorage(state,id)`, `setMiningArea(state,x,z)`, all returning `{ok,reason}`. Production advances inside `tick` only when `dt>0`; machines use the previous tick's `power.powered`. Paths are runtime-only caches, never saved.
`world.setGhost(type,x,z,rotation,valid,line)` accepts `type:'mine'` and an optional belt route of cells.

## Shared inventory presentation

`item-models.js` loads `assets/inventory/items.glb`, exported from the icon library's
actual Blender meshes. `loadItemLibrary(loader)` returns shared ground-centred,
unit-size templates: `get(item)`, `create(item,size)`, `batch(item,capacity,size)`,
`replace(root,target,item,size)` and `dispose()`. A batch has `root`, `meshes`,
`set(index,matrix)`, `finish(count)` and `dispose()`. Each material part is one
instanced draw; disposing a batch does not dispose shared geometry or materials.
The owning world disposes the library after disposing its views. Belts, rover/hauler
cargo, food, salvage and cave loot use the same meshes as the inventory icons.
Cave views accept an optional item library after `zone` and retain collection and
discovery visibility. The orbital view owns its separate library for its renderer.
This is presentation only: simulation items, recipes and saves are unchanged.
Belts: `rotateBelt(state,id,rotation)` redirects an existing belt; `beltTurns(state)` (production.js) maps belt id to 0 straight, 1/-1 corner fed from the right/left side, derived from neighbours (never saved).
## Phase C additions
Definitions gain `key` (build shortcut letter), `layer` (`'floor'` room squares: `habitat`, `greenhouse`, `airlock`; `'interior'` fittings: `growbed`, `galley`, `recycler`, which need finished floor of the `needs` room type), `paint` (drag-painted), `power` (kW per finished square) and `inset` (fitting collision shrink). A fitting may share its cell with a floor square; nothing else overlaps. `ITEM_INFO` lists carried items (`metal`, `silicon`, `crop`, `meal`) with stack sizes and `food` value.
State version 3: `inventory` is ten slots, each `null` or `{item,count}` (`inventory.js`: `count`, `room`, `add` returns leftover, `remove`, `canFit`); `reserves:{oxygen,water}`; `player.satiety` 0–100 (optional on load, default 100). Floor squares carry `air`; grow beds `grow`,`watered`; galleys `crops`,`work`,`meals`; recyclers `work`. Versions 1–2 migrate (each 2×2 habitat module becomes four squares, front-left square an airlock unless facing another module). New sim export `interact(state,id)` (crate, grow bed, galley). `life.js`: `roomStatus(state)`, `stepLife`, `lifeDemand`, `hunger(satiety)` → `{speed,build,label}`, `eat(state,slot)`, `lifeAction(state,b)`.
Rooms: `habitat.js` `habitatLayout(buildings,{blueprints})` returns joined rooms of touching squares, wall segments (`kind` wall, window, glass or door), airlocks (door on the airlock square's `rotation` edge, `apron` cell outside) and a collision grid; `wallBlocks` is used by `movePlayer`; `trapsPlayer(buildings,x,z,r)` reports a wall overlap or a room with no usable airlock. Robots treat finished rooms and fittings as solid. Airlocks must back onto a habitat or greenhouse and open onto clear ground; solids and room squares may not cover an airlock entrance. `playerObstructs(state,b)` reports a blueprint whose completion would shut the player in; `construct` refuses it and the world tints it red. `habitatView.lights()` lists ceiling light positions for the shared light pool.
## Phase D additions
Definitions add `melter` (1×2, key `i`, one input at local 0,0 facing −Z) and the carried items `ice` and `core` (stack 1). `production.js` exports `MELT`, `total(inv)` and `melterReady(state,b)`; hoppers and crates hold `ice`, melters `inv{ice}` and `work`, robots `load` (the kind of cargo). `miningCells` cells carry `kind`; an area touching ice returns only its ice cells. `terrain.js` exports `missionSite()` (crater centre, radius, depth and `lander`) and `iceAt(x,z)`; the lander blocks movement and placement.
State version 4 adds `mission:{step,visited,salvage,installed,legacy,melted,sighted}`. `mission.js`: `STEPS`, `objective(state)` → `{id,objective,message,step,count,target}` or `{done,message}`, `processorUnlocked`, `missionAction(state)` (`hold` for salvage), `salvage(state,dt)`, `installCore(state)`, `noteSighting(state)`, `stepMission` (called by `tick`). `sim.js` exports `PROCESSOR_LOCKED`; `validatePlacement` refuses the processor until unlocked. Versions 1–3 load with `legacy:true` (already repaired) and may not contain melters. `watcher.js` is presentation state outside the save: `createWatcher()`, `stepWatcher(w,state,dt)` returns `'vanished'` once per sighting. `world.update(state,dt,pose,watcher)`; UI view gains `objective` (with `distance`), `missionUse` and `locked`, and `ui.say(text)` shows a 14 s ship AI aside.

## Status lamps and glyphs
Work lights are retired: `deserialize` drops `lamp` buildings, and every built outdoor machine feeds the shared six-light pool at night. Every machine model carries a `Lamp` node (status lamp material); batteries add `Cell1`–`Cell5`, melters and hoppers a `Level` gauge (`blender/status_parts.py`). `status-lamps.js` `createStatusLamps()` → `{prepare(template), attach(root) → {set(level,shown), cells(fraction,level), fill(fraction,kind)}, update(t,daylight), dispose()}`; lamps in one state share a material. `building-status.js` statuses are `{text,read,tone,fill?,glyph?}`; `lampLevel(status)` maps tone to `ok|low|fault|idle|off`. Over the machine, the world floats one glyph only for `warning` tones (`glyph` of `power`, `ice`, `water`, else `alert`) and for charging batteries and rovers (`charging`). Buildings carry a per-type `serial` (`defs.js` `CODES`, `tagOf`), validated on load and assigned to old saves.
Definitions keep `key` only for constant tools (conveyor `c`, habitat `h`; the UI adds mining area `m`, dismantle `z`); `b` toggles the build menu via `ui.toggleMenu()`.

## Robots and zones (save version 5)
`state.miningAreas` is up to `MAX_MINING_AREAS` (4) non-overlapping `{id,x,z}` zones with `state.nextAreaId`; version 4 saves turn `miningArea` into zone 1. `sim.js`: `setMiningArea` adds a zone (`{ok,id,reason}`), `miningAreaReason`, `removeMiningArea(state,id)`, `assignRover(state,robotId,areaId|null)`. Rovers carry an optional `area` (absent means Auto). `production.js`: `miningCells(state,areaId?)` (cells carry `area`), `areaKind`, `remainingRegolith(state,areaId?)`, `hasMelter`, `dockSpace(dock,load)`. Regolith unloads only at hoppers and ice only into melters (docking beside them, waiting while a melter is full); ice is not dug until a melter stands. Blueprint statuses carry `glyph:'build'`; `ui.toggleRobots()` and `g` open the Robots panel.

## Phase E: satellites, launch and research (save version 6)
Definitions add `fabricator` (2×2), `assembler` (2×3), `electrolyser` (1×2), `tank` (2×2, `nearPad`: a footprint cell must touch the ring around the pad), `dock` (2×2) and `roverbay` (2×2, `research:'roverbay'`, refused by `validatePlacement` until researched). Items add `frame`, `wing`, `chip` (stack 10) and `satellite` (stack 1); `PARTS` gives each part's input. Crates hold every item.
`production.js`: `FAB`, `ASSEMBLY`, `KIT`, `RECIPES` (`kit`, `frame`, `wing`, `chip`), `currentPart(b)`, `cycleRecipe(b)`, `fabricatorReady`, `assemblerReady`, `machineRoom(b,item)`; fabricators carry `inv{metal,silicon}`, `out{frame,wing,chip}`, `recipe`, `step`, `work`; assemblers `inv{frame,wing,chip}`, `out{satellite}`, `work`. Both accept belts and push outputs like the processor. `drive`, `nearestDock(state,r,types|predicate)`, `robotTopology` and the unreachable memory are shared with haulers. Docking prefers sides without belt ports and falls back to port cells (crates).
State adds `ship:{status:'pad'|'ascent'|'orbit'|'descent',t,fuel,payload,hold}`, `satellites` (count in orbit) and `research:{bank,selected,progress:{id:n},done:[id]}`. Robots add `kind:'hauler'` `{id,home,x,z,facing,task,charge,cargo,load,target,job}`; jobs and targets are replanned after loading. Electrolysers carry `work`, tanks `fuel`.
`space.js`: `LAUNCH`, `ELECTROLYSIS`, `TECHS`, `ROBOT_COST`, `ROBOT_LIMIT`, `stepSpace`, `spaceDemand`, `shipAction(state)` (`hold` to launch), `loadSatellite`, `holdLaunch(state,dt)`, `releaseLaunch`, `recallShip`, `selectResearch(state,id|null)`, `buildRobot(state,id)`, `machineAction(state,b)`, `lockedReason(state,type)`, `touchesPad(b)`. `hauler.js`: `HAULER`, `stepHaulers`, `haulerDemand`, `stockOf`, `restoreHauler`. `interact` covers the fabricator (recipe), assembler (take satellite), dock and rover bay (build a robot). `building-status.js` adds `shipStatus(state)`; new glyphs `satellite`, `fuel`, `launch` (fuel and launch carry a ring). `createOrbitView({onReturn,onResearch,onClose})` → `{open,show(),close(),toggle(),update(state,dt),dispose()}`; the UI adds `onOrbit` and an orbit badge with the satellite count.

Storage: crates carry `slots` (12 × `null|{item,count}`, the inventory format) instead of `inv`; older `inv` crates convert on load. Items add `regolith` (stack 100) and `ice` (stack 50). `storage.js`: `crates`, `inReach` (surface, within `BASE_REACH` m of a crate), `baseCount`, `stash`/`draw`, `available`/`canPay`/`missing`/`pay` (pockets first, then crates when in reach), `canReceive`/`receive` (pockets first, overflow into crates), `storeSlot`, `takeSlot`, `storeAll`, `ledger(state)` → rows `{item,total,stored,pockets,crates[{id,tag,n}],machines[{tag,n,role}],belts,robots[{id,kind,n,to}]}`. `interact` on a crate returns `{open:'crate'}`; `collectStorage` takes everything that fits.
